# 自定义用户组目录与刷新修复（2026-10-20）

## 问题与原因

管理员在特殊倍率规则中创建 `wholesale-ultra` 并保存三条规则后，用户编辑抽屉仍只列出旧用户组。特殊倍率区域还在该组名旁显示红色“Not in pricing table”警告。

三个问题叠加：

- 用户编辑调用 `/api/group/tiers`，该目录只来源于贡献等级阈值，漏掉特殊倍率声明的用户身份。
- 抽屉在隐藏时仍挂载，列表缓存五分钟；保存配置没有使该查询失效，重新打开抽屉也不会重新请求。
- 特殊倍率行把用户身份组拿去与渠道计费组目录比较，错误地要求身份组同时有基础计费倍率。

## 行为修复

新增管理员接口 `/api/group/user-groups`，合并 `free`、等级目录、启用的商业身份组、特殊倍率和特殊可用分组的**外层用户组键**。去重，排除空名与 `auto`，按名称排序并把 `free` 放在最前。

渠道目录 `/api/group/` 和订阅等级目录 `/api/group/tiers` 保持原有职责。新接口不会为自定义组添加贡献门槛、商业属性、模型权限或基础价格。

用户抽屉使用独立查询键，打开时获取当前目录，切回窗口时重新验证；保存相关配置后使用户目录缓存失效。特殊倍率表中移除身份组的错误警告，保留实际计费目标缺失时的警告。

## 验证

先复现失败，再修复：

- 后端接口测试覆盖特殊倍率组、空规则组、可见性组、商业组、去重以及排除计费目标；同时断言渠道与订阅目录不混入新用户组。
- 前端使用真实用户编辑抽屉、表单和 QueryClient，覆盖选择自定义组并提交、重新打开获取新组、保存倍率后更新已打开抽屉。
- 警告测试确认用户身份组不再误报，未登记的计费目标仍会警告。
- 相关前端 20 项测试、后端相关测试、类型检查、涉及文件 lint、前端构建和 Linux 二进制构建作为发布检查。

用户明确要求将用户 35（`oidc_32`）从 `wholesale-plus` 切换到 `wholesale-ultra`。通过现有管理员 API 完成并在两个实例读取核对；保留正常用户组变更的缓存刷新、会话撤销和审计流程。
